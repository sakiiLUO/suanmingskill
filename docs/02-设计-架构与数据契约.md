# 设计：架构与数据契约

## 一、分层

```text
用户输入（生日/出生地/性别/问题）
        │
        ▼
SKILL.md（行为内核）─── 决定问什么、按需加载哪份 references、怎么输出
        │
        ├── scripts/paipan.py ──┐
        ├── scripts/hepan.py ───┤ 计算层：可复核，确定性输出
        ├── scripts/archive.py ─┘
        │        │
        │        └── vendor/lunar_python（MIT，未修改）
        │
        └── references/*.md（解释层：假设、边界、话术）
                 │
                 ▼
        【命理简报】──► goutoujunshi（关系策略、话术、情绪支持）
```

**关键约束**：计算层不产生解释，解释层不改写计算；两者在回答里分段呈现。这样“盘算错了”和“话说过头了”可以分别定位、分别修。

## 二、为什么用 skill 而不是写成脚本工具

- skill 的形态（`SKILL.md` + 按需加载的 references + 可选 scripts）与狗头军师一致，用户可以在同一套目录里管理两个 skill，交接协议也只需文档级约定。
- DSH 的 skill provider 会**监视目录并热加载**，改 `SKILL.md` 或 references 不需要重启。
- 不需要写 Cordis 插件；排盘是纯本地计算，不需要工具注册。

## 三、DSH 的 skill 发现规则（落地依据）

| Rank | 来源 | 路径 |
| --- | --- | --- |
| 100 | 项目 | `<项目根>/.dsh/skills` |
| 200 | 项目 | `<项目根>/.agents/skills` |
| 300 | 自定义 | `Config.customSkillDirs` |
| 400 | 用户 | `~/.dsh/skills` |
| 500 | 用户 | `~/.agents/skills` |
| 600 | 随包 | `bundledSkillDir` |

- 项目根 = 含 `.git` 的最近祖先，否则是 cwd。
- skill 形态：`<name>/SKILL.md` 目录包，或 `<name>.md` 平铺；**不支持**嵌套 `**/SKILL.md`。
- frontmatter：必填 `name`、`description`；可选 `whenToUse`、`metadata`、`disable-model-invocation`、`user-invocable`。
- 发布版仓库根目录就是 skill 本身（`SKILL.md` 在仓库根），安装时把仓库目录复制为 `<skills根>/suanming/` 即可；开发期也可以用 Junction 链过去。

## 四、数据契约

### 4.1 排盘输出 `suanming.paipan.v1`

```json

  "input": {"birth_clock": "...", "gender": "male|female", "tz_hours": 8,

  "time_correction": {"clock": "...", "standard_time": "...", "dst_minutes": 0,
                      "longitude_correction_minutes": 0.62, "eot_minutes": -4.5,
                      "true_solar_time": "...", "late_zi_applied": false, "shichen": "未"},
  "lunar": {"text": "...", "year": 1995, "month": 7, "day": 22, "is_leap_month": false},

  "wuxing": {"counts": {}, "percent": {}, "strongest": "...", "weakest": "...", "note": "..."},
```

**契约规则**：字段只增不改；`warnings` 是给模型看的“必须复述或追问”的清单；`wuxing.note` 必须随字段一起出现，防止模型把它当旺衰定论。

### 4.2 合盘输出 `suanming.hepan.v1`

```json
{
  "schema": "suanming.hepan.v1",
  "a": {"name": "A", "pillars": ["乙亥","甲申","庚辰","癸未"], "day_master": "庚金"},
  "b": {"name": "B", "pillars": ["丙子","辛卯","甲辰","戊辰"], "day_master": "甲木"},
  "axes": [{"axis": "日支（亲密互动位）", "level": "需磨合|偏合|中性|信息不足",
            "evidence": "...", "confidence": "高|中|低"}],
  "tally": {"偏合": 0, "中性": 1, "需磨合": 2, "信息不足": 1},
  "framing": "合盘只提供提问角度……",
  "disclaimer": "..."
}
```

**刻意不设总分**。总分会被模型和用户当成结论，违背“命理是提问角度”的定位。`level` 是离散标签，`confidence` 强制暴露不确定性。

### 4.3 命理档案 `suanming.profile.v1`

字段固定为 `name / gender / birth_clock / city / longitude / tz_hours / dst_mode / late_zi / pillars / day_master / notes / updated_at / notice`。不存聊天原文与截图。写入必须 `--consent`。

## 五、错误与降级

| 情况 | 行为 |
| --- | --- |
| `lunar_python` 缺失 | `engine.ensure_engine()` 打印安装命令并退出码 2；SKILL.md 要求明说“现在排不了盘”，不口算 |
| 生日格式错 | argparse 报错，提示 `YYYY-MM-DD HH:MM` |
| 未知城市 | 报错并提示改用 `--longitude` |
| 时辰边界 ≤10 分钟 | 输出 warning，要求回答里声明不确定性 |
| 出生信息不全 | 不排盘；按“时辰不确定”流程给 2–3 个候选盘的分叉结论 |

## 六、测试策略

| 类型 | 内容 | 文件 |
| --- | --- | --- |
| 不变量 | 60 天日柱连续；五鼠遁时干规则；均时差范围 | `tests/test_suanming.py` |
| 边界 | 立春前后年柱/月柱切换；夏令时首尾日；晚子时两种口径 | 同上 |
| 回归 | 1995-08-17 14:30 杭州 → 乙亥甲申庚辰癸未；1990-06-15 09:10 上海 → 命中午时回拨 | 同上 |
| 契约 | 输出 JSON 必含字段；合盘 axes 结构 | 同上 |
| 打包 | 文件齐全、frontmatter、引用路径、脚本可编译、无绝对路径/密钥 | `scripts/validate_skill.py` |

## 七、风险与已知限制

1. **均时差用近似公式**：误差数十秒，对时辰粒度足够；不做分钟级天文级校验。
2. **不输出旺衰喜忌**：这是有意的克制，也可能是“不够专业”的抱怨来源；升级路径是引入人工校核的规则包，而不是让模型自由发挥。
3. **夏令时只覆盖中国 1986–1991**：海外出生需要用户提供当地规则。
4. **紫微/六爻未做**：范围控制；v2 用 iztro（MIT）做 Node 子进程。
5. **合盘维度权重未被验证**：所以不给总分，只给维度与证据。
6. **模型可能把假设说过头**：SKILL.md 的“绝对词禁令 + 反向可能 + 验证动作”是主要防线，但仍是提示词级约束，不是程序级强制。
