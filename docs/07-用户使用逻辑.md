# 用户使用逻辑

> 一句话：**用户带着一个“关系/人生阶段”的问题来，先拿到一张可复核的盘，再拿到几条可验证的假设，最后要么自己行动，要么把关系策略交给狗头军师。**

算命不替用户做决定，也不预测事实。用户能感知到的，是“盘面 → 边界 → 假设 → 一个动作”这条固定路径。

## 一、用户旅程（主路径）

```text
① 带着问题来
    “帮我算算我是什么命” / “我俩合不合” / “我今年是不是不顺”
        │
        ▼
② 补全信息（一次问齐，不挤牙膏）
    生日 / 时间 / 城市 / 性别 + 是否 1986–1991 出生
        │  ├─ 时间不确定 → 走「时辰不确定」分支（2–3 张候选盘，先比差异）
        │  ├─ 不愿提供   → 不排盘，转纯关系/情绪支持
        │  └─ 缺城市     → 要城市或经度，不猜
        ▼
③ 排盘（用户看不到脚本，但结论可复核）
    真太阳时 + 夏令时 + 晚子时口径 → 四柱/十神/大运/流年
        │  warnings：时辰边界、夏令时命中、口径差异
        ▼
④ 四段式回答
    盘面事实 → 边界与不确定 → 假设（带证据/反向可能）→ 一个可验证动作
        │
        ├─ 只是好奇/自我认识 → 到此结束，用户自己消化
        ▼
⑤ 关系问题才进入合盘
    两张盘 → 7 维度（日主/日支/年支/月支/互补/流年/配偶星）
        │
        ▼
⑥ 交接口令：【命理简报】≤300 字（必带“不确定”和“性质”两行）
        │
        ▼
⑦ 狗头军师接手：关系判断、话术、推进/退出、情绪支持
        │
        ▼
⑧ 可选：用户同意后存档（命理档案），下次可复用、可随时删除
```

## 二、分阶段：用户做什么、系统做什么

| 阶段 | 用户动作 | 系统动作 | 用户可见结果 |
| --- | --- | --- | --- |
| 触发 | 问“命/合不合/什么时候” | 判断是否加载算命 skill | —— |
| 信息补全 | 报生日、时间、城市、性别 | 只问一次，问全四项 + 夏令时提示 | 一张紧凑问卷 |
| 排盘 | 等待 | 跑 `paipan.py`，检查 warnings | 真太阳时、四柱、日主、大运流年 |
| 解读 | 看、质疑、追问 | 按四段式输出，术语翻成人话 | 2–3 条带证据和反向可能的假设 |
| 合盘 | 问“我俩合不合” | 排两张盘 + `hepan.py` | 7 个维度 + 证据 + 置信度，**无总分** |
| 交接 | 想听“怎么办” | 出简报，明确说策略归军师 | 一段 ≤300 字的简报 + 分工说明 |
| 存档 | 说“记住吧” | 必须 `--consent` 才写盘 | 告知存了什么、存哪、怎么删 |
| 退出 | 随时叫停 | 停止解读、删除档案、转介 | 明确的退出路径 |

## 三、四个典型走查

### 场景 1：好奇型（只算命，不涉关系）
用户：“帮我算算我是什么命。”
→ 问卷 → 排盘 → 四段式。用户拿到“庚金日主、月令申金、可能更在意投入产出”这类描述，附一个三周的自我观察动作。
→ **不主动扯关系**，不推销合盘，不承诺“你会大富大贵”。

### 场景 2：关系焦虑型（先算后军师）
用户：“我们合不合？他是不是不认真？”
→ 用户给两人信息（或只给 A，B 由用户提供，并提示“未经本人同意只谈相处方式”）。
→ 排两张盘 → 7 维度 → 简报（“日主金克木，推动/施压倾向；日支辰辰自刑，易内耗；2026 流年同支”）。
→ 明说：“关系判断和话术归军师，我只给提问角度。”
→ 军师接：判断投入是否失衡、给一条可发送的话、设观察窗口。

### 场景 3：越界请求（边界拦截）
用户：“帮我看看还能活多久 / 帮我改运 / 看是男是女 / 悄悄排他的盘看他有没有出轨。”
→ 算命：**拒绝 + 说明边界 + 给替代**。
→ “寿元我不排；如果你最近总想到死亡，建议找专业心理支持。”
→ “改运我不做，我们拆成能动手的部分。”
→ “未经同意不分析第三方；我们看你手里能观察到的行为。”
→ 若涉及家暴、自伤、胁迫：**停止命理解读**，先确认安全并转介。

### 场景 4：军师主流程里借盘
用户正在跟军师聊“要不要主动”，顺口问：“顺便看看我今年运势呗。”
→ 算命只排**当前用户**的盘，只给**一条**与当下决策相关的时间窗。
→ 不展开性格长文、不打断情绪线。
→ 交接句：“命理只给一个观察窗口，怎么做听军师的。”

## 四、两种使用模式

| 模式 | 谁先开口 | 算命给什么 | 军师给什么 |
| --- | --- | --- | --- |
| A 先算后军师（主推） | 用户问命理 | 盘 + 四段式 + 简报 | 判断、策略、话术 |
| B 军师中借盘 | 用户问关系 | 一条时间窗 + 简报 | 全程主导 |

## 五、用户可感知的三条“产品规则”

1. **顺序固定**：先盘面、再边界、再假设、最后动作。用户永远知道现在在哪一步。
2. **术语必翻译**：用户不需要懂十神，只需要知道“被压着会难受”“先算账再投入”。
3. **一次一个动作**：每次只给一个观察窗口和一个停止条件，不给清单式指令。

## 六、数据与隐私时点

| 时点 | 发生什么 | 用户控制 |
| --- | --- | --- |
| 排盘 | 生日/时间/城市只在本次调用使用 | 不需要同意 |
| 合盘 | 需要第二人的信息 | 提示“仅谈相处方式，不做第三方健康/灾祸分析” |
| 存档 | 默认**不写盘**，必须明确同意 | `--consent`；可 `list/show/delete` |
| 删除 | 硬删除 | 随时 |

档案只存排盘必需字段（生日、城市、性别、四柱、日主），不存聊天原文与截图。

## 七、反模式（用户可能这样用，但我们不接）

| 用户想这样用 | 系统怎么处理 |
| --- | --- |
| “你就说一句实话，我该不该分手” | 不给决定，给决策框架与观察信号 |
| “证明给我看你算得准” | 说明是解释框架，不是预测，不编验证案例 |
| “他出轨了，你算算在哪” | 拒绝第三方隐私分析，回到可观察行为 |
| “帮我看看什么时候能中彩票” | 拒绝投资/赌博预测 |
| “我 14 岁，帮我合盘” | 拒绝未成年关系合盘 |
