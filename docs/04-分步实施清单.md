# 分步实施清单（从 0 到能用的算命 skill）

> 适用：想从零复制一遍这套做法的人。顺序不要跳——每一步的验收没过，不要进入下一步。
> 已按此流程做出本仓库；每步都给了可运行的验收命令。

---

## 阶段 0：先定边界（10 分钟）

**目标**：在写代码前写清“做什么、不做什么”，否则后面每一步都会被范围拖垮。

1. 写一句话定位：*“排盘与合盘，只出盘面和假设，关系策略交给狗头军师。”*
2. 列禁止项：生死、寿元、疾病、灾祸、官司、胎儿性别、投资、改运收费、PUA、第三方隐私、未成年人合婚。
3. 定形态：给 Codex/Claude/DSH 用的 skill（`SKILL.md` + references + scripts），不是 App、不是 API 服务。

**验收**：能一句话回答“用户问‘我什么时候死’，我怎么办”。

---

## 阶段 1：调研同类项目，先选轮子再选写法（1–2 小时）

**目标**：不重复造历算，也不引入来源不明的代码。

1. 搜 GitHub：`八字 排盘 python`、`bazi calculator`、`紫微斗数 开源`、`lunar calendar 干支`、`sxtwl`、`iztro`。
2. 对每个候选记录六件事：**许可证（看 LICENSE 原文）**、最近提交、依赖、能力边界、issue 里的已知坑、是否可商用/再分发。
3. 特别核实：`lunar-python`（MIT）、`sxtwl`（BSD-3）、`iztro`（MIT）、`ziwei-doushu`（代码 MIT / 语料 CC BY-NC-SA）、`china-testing/bazi`（**无 LICENSE = 不可复制**）。
4. 只借鉴**设计与坑清单**（真太阳时、1986–1991 夏令时、闰月口径、晚子时、立春边界），断语与语料自己写。

**产出**：`docs/01-调研-同类开源项目对比.md` 的速览表 + 选型结论。

**验收**：能说清“为什么用 A 不用 B”，且每个依赖都有明确许可证。

---

## 阶段 2：搭计算层（半天）

**目标**：先把盘算准，一行解读都还没有。

1. 建目录：`suanming/{scripts,references,tests,vendor,agents}`（仓库根即 skill 根）。
2. 装依赖并锁定版本：`python -m pip install lunar-python==1.4.8`；要离线就把未修改的包放进 `vendor/`（保留 `dist-info/LICENSE`）。
3. 写 `scripts/engine.py`：优先 vendor，其次已安装，缺依赖时给明确安装提示（**不要静默失败，也不要口算**）。
4. 写 `scripts/paipan.py`：生日 → 四柱/藏干/十神/纳音/地势/空亡/大运/流年 → JSON + brief 两种输出。
5. 跑通一个样例，肉眼核对四柱。

**验收**：

```bash
python scripts/paipan.py --birth "1995-08-17 14:30" --gender male --city 杭州 --format brief
# 期望：四柱 乙亥 甲申 庚辰 癸未，日主庚金
```

---

## 阶段 3：补规则层——上游缺的正是你最容易错的（半天）

**目标**：真太阳时、夏令时、晚子时、边界告警。这四件事决定“盘对不对”，也决定用户信不信你。

1. `scripts/solartime.py`：
   - 经度差：`(经度 − 时区×15) × 4` 分钟。
   - 均时差：NOAA 简化公式（±20 秒够用）。
   - 1986–1991 中国夏令时表（4–9 月，回拨 60 分钟），`--dst auto|on|off`。
   - 时辰序号与边界距离（≤10 分钟必须告警）。
2. 晚子时：`--late-zi next_day|same_day`，两种口径都输出、都声明。
3. 边界提示：`warnings` 数组，SKILL.md 要求模型逐条复述或追问。
4. 城市经度表（40 个常用城市）+ `--longitude` 兜底。

**验收**：

```bash
python scripts/paipan.py --birth "1990-06-15 09:10" --gender male --city 上海 --format brief
# 期望：提示命中夏令时，回拨 60 分钟后为辰时
python scripts/paipan.py --birth "1995-08-17 23:30" --gender male --city 杭州 --format brief
# 期望：晚子时提示，日柱取次日 辛巳
```

---

## 阶段 4：写解读层（1–2 天，最花时间）

**目标**：把“盘”翻译成“人话”，但每句话都带证据、反向可能和验证动作。

1. 定输出结构（四段式）：盘面事实 → 边界与不确定 → 假设层（2–3 条，带证据/反向可能）→ 可验证的小动作。
2. 写 references（按需加载，单份 < 40KB）：
   - `00-导读与加载路由.md`（怎么选文件、硬规则）
   - `01-排盘规则与真太阳时.md`（历法坑 + 回归样例）
   - `02-十神-五行-格局读法.md`（术语翻译 + 禁止清单）
   - `03-合盘与关系维度.md`（7 维度、无总分）
   - `04-大运流年与时间窗.md`（把“什么时候”改成“看到什么就行动”）
   - `05-伦理边界与话术红黑线.md`（红线/黄线/危机转介）
   - `06-命理档案与交接协议.md`
3. `scripts/hepan.py`：日主五行、日支/年支/月支关系、五行互补、同年流年、配偶星 → `axes` + `level` + `confidence`，**不输出总分**。
4. 定 `SKILL.md` 骨架：定位 → 核心原则 → 首次使用问卷 → 排盘流程（命令）→ 输出结构 → 合盘与配合 → 按需加载表 → 安全边界 → 常见坑。

**验收**：随便给一个盘，能产出四段式回答；每条假设都有盘面证据行。

---

## 阶段 5：接上狗头军师（半天）

**目标**：两边各说各的边界内的话。

1. 读一遍 goutoujunshi 的 `SKILL.md`：它管情绪、事实拆分、利益判断、话术、档案。
2. 写分工表（谁负责什么）与【命理简报】格式（≤300 字，必带“不确定”和“性质”两行）。
3. 定冲突规则：命理 vs 现实行为 → **行为优先**；命理 vs 军师策略 → **军师优先**。
4. 档案不互通：算命用 `archive.py`（JSON、需同意、可删），军师用它自己的 SQLite 记忆；只传简报。
5. 写 `docs/03-与狗头军师配合协议.md` 与联合验收清单。

**验收**：问“我俩合不合”，先出简报再给策略；问“这句话怎么回”，不先要求排盘。

---

## 阶段 6：测试与打包校验（半天）

1. `tests/test_suanming.py`（unittest，零额外依赖）：
   - 不变量：60 天日柱连续 +1；五鼠遁时干规则；均时差在 −17.5~+17.5 分钟。
   - 边界：立春前后年柱/月柱切换；夏令时首尾日；晚子时两口径。
   - 回归：固定样例锁定四柱。
   - 契约：JSON 必含字段。
2. `scripts/lint_reply.py`：把“不许绝对化/断生死/改运/伪精确总分”做成可执行检查，并加红队测试（见 `docs/05`）。
3. `scripts/validate_skill.py`：文件齐全、frontmatter、references 引用存在、脚本可编译、单份 reference 体积、NOTICE 许可声明、绝对路径/密钥/TODO 扫描。
4. `NOTICE.md`：依赖名、版本、许可证、来源链接；声明“借鉴了哪些设计、未使用哪些代码”。

**验收**：

```bash
python -m unittest discover -s tests -v     # 全绿
python scripts/validate_skill.py --verbose  # 校验通过
```

---

## 阶段 7：装进宿主并验证触发（30 分钟）

1. DSH 项目级安装（用 Junction，改源码即改 skill）：

```powershell
New-Item -ItemType Directory -Force ".dsh\skills" | Out-Null
New-Item -ItemType Junction -Path ".dsh\skills\suanming" -Target "$PWD"
```

2. 用户级安装：复制到 `%USERPROFILE%\.dsh\skills\suanming\`（DSH）；Codex 用 `~/.codex/skills/`（带 `agents/openai.yaml`）。
3. 验证：
   - 新会话里 skill 目录出现 `suanming`，描述能被正确触发。
   - 说“帮我算算八字”，模型会先问四样信息，再跑脚本。
   - 故意给错生日格式，模型会纠正而不是瞎算。
4. 热加载验证：改 `SKILL.md` 一句话，下一轮目录应刷新（DSH 会监视根目录）。

**验收**：从用户视角走一遍“问八字 → 排盘 → 四段式 → 简报”，全程没有手工贴命令。

---

## 阶段 8：发布与维护（持续）

1. 许可证：本项目建议 MIT；`NOTICE.md` 与 `vendor/*/LICENSE` 一起分发。
2. 版本锁定：`requirements.txt` 写 `lunar-python==1.4.8`；升级前先跑回归。
3. CI（可选，GitHub Actions 三行）：`python -m unittest` + `python scripts/validate_skill.py`。
4. 迭代方向（按性价比）：
   - 先用真实对话调 SKILL.md 的话术边界（最高性价比）；
   - 再做紫微（iztro/MIT，Node 子进程）；
   - 六爻/塔罗按 `divicast`（MIT）的 JSON 设计另起 skill，不要塞进这里。
5. 每次改动记录三件事：改了什么规则、为什么、哪个测试锁住了它。
